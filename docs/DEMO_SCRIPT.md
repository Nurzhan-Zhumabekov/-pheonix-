# Сценарий защиты (до 5 минут)

План из Student Guide (стр. 4): 1 минута интерфейс и диалог, 2 минуты оценка, обоснование, переход к реплике, пример N/A и итог, 1 минута апелляция, решение и новый итог, 1 минута изменение критерия и применение чек-листа. Время по пунктам ориентировочное, вся презентация должна уложиться в 5 минут.

## Подготовка заранее

- [ ] Выбрать диалог для показа оценки: желательно с одним N/A и заметной ошибкой оператора.
- [ ] Выбрать звонок: показать переход от критерия к реплике и плееру.
- [ ] Выбрать критерий для апелляции, где оценка заметно меняется.
- [ ] Подготовить правку критерия, которая видимо меняет результат (например, изменить вес или шкалу). На проверке организаторы предложат заменить один критерий: будем готовы сделать это через интерфейс.
- [ ] Контрольные диалоги запущены заранее, результаты готовы.
- [ ] Запасной вариант на случай сбоя API или модели: запись экрана и заранее сохранённая оценка. Показывать её только с оговоркой, что это запись.
- [ ] Решить, кто что говорит. Репетиция минимум один раз по секундомеру.

## Сценарий

| Время | Что показываем |
|---|---|
| 0:00–1:00 | Одно предложение о подходе: LLM выбирает ответ и цитату, итог считает код. Интерфейс: загрузка из API, список диалогов, открыть диалог, транскрипт, для звонка плеер |
| 1:00–3:00 | Запуск оценки: ответ, баллы, вес, объяснение, переход по цитате к реплике. Критерий с N/A и причина, критерий с пропущенным действием и место, где оно ожидалось. Итог и секции |
| 3:00–4:00 | Апелляция как отдельное действие: выбрать критерий, комментарий. Решение проверяющего как отдельное действие: исходная оценка, решение, финальный результат, новый итог |
| 4:00–5:00 | Изменить критерий в чек-листе, сохранить, применить к диалогу, показать, что результат изменился. В конце: модель, стоимость одной оценки, ссылка на репозиторий |

Регистрации и входа нет, так и говорим.

## Если спросят

- Откуда доказательство: цитата дословно из транскрипта, проверяется кодом.
- Что если критерий заменят: рубрика берётся из конфига, правка кода не нужна.
- Как считается итог: [SCORING.md](SCORING.md).
- Как проверяли точность: ручная разметка DEV и проверочные диалоги. Называем честные цифры, не округляем в свою пользу.
- Распознавание речи: транскрипты выданы. Для дикции и интонации нужен звук. Если не анализировали, говорим прямо.
- Какая модель и сколько стоит одна оценка: цифры из README.
