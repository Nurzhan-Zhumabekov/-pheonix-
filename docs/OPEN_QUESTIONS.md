# Что подтверждено и что нет

Состояние на 7 ноября, около 15:00. Файлы PDF (чек-лист и Student Guide v3) сверены с оригиналами. Сообщения из Telegram даны в пересказе, их стоит сверить с чатом.

## Из выданных PDF (проверено)

- Один чек-лист на RU, KZ и EN, 8 критериев, секции: «Начало и понимание запроса» (1, 2), «Безопасность и решение» (3, 4), «Ведение и завершение диалога» (5, 6, 7), «Грубые нарушения» (8).
- Порядок расчёта: N/A только там, где разрешён и выполнено условие; Да даёт полный вес, Нет ноль; верхняя ступень шкалы даёт полный вес; N/A исключается, веса перераспределяются, максимум 100; округление до двух знаков; нет применимых критериев с весом, итог не считается; грубые ошибки отдельно.
- В задании указан порог первой реакции 3 минуты, теги и вложения в оценку не входят.
- На контроле организаторы предложат заменить один критерий. Нужно сохранить новый чек-лист через интерфейс и применить к выданным диалогам.
- Через 23 часа открываются контрольные транскрипты, нужно запустить их заранее. Через 24 часа стоп-код, фиксируется последний коммит. Обработка и смена чек-листа через интерфейс допустимы на зафиксированной версии.
- До стоп-кода: открытый Git-репозиторий, ссылка организаторам заранее, README с шагами запуска.
- Защита до 5 минут: 1 / 2 / 1 / 1 минуты (интерфейс, оценка, апелляция, смена критерия).
- API: GET с `group_id`, ответ `error`, `isSuccess`, `data` (`dataset_group_id`, `total_records`, `records`). Язык RU, KZ, EN; канал `agent chat` или `voice call`; время чатов MM:SS, звонков ISO 8601 с часовым поясом; `audio_url` у чатов пустой.
- Модель, серверная часть и хранилище на выбор команды. Регистрации и входа нет. Для CORS: запрашивать данные через серверную часть или локальный адаптер.
- Интерфейс на HTML, CSS, JavaScript с возможностью адаптации как HTML-компонент Dynamics 365.

## Из Telegram (пересказ)

- Контрольный набор из 10 неизвестных транскриптов берётся через тот же API, что DEV, с другим `group_id` (Максим, Q&A Organizers, 7 нояб, 12:58).
- Главный ориентир отбора топ-50: близость оценок к Ground Truth на этих 10 диалогах. Учитывают также функциональность, удобство, реальную обработку новых данных, разнообразие подходов. Hardcoded результаты недопустимы.
- Для звонков логика восьми критериев та же, письменные признаки адаптируются к речи. Критерий 6: логичность, понятность, уместность выражений, управление паузами; при наличии аудио можно анализировать темп и дикцию (Николай, 12:43).
- Отдельного справочника с эталонными ответами для контрольных разговоров нет. Материалы Freedom Broker по продуктам существуют, доступность участникам не уточнена.
- TypeScript + Tailwind CSS допустимы (Максим). React отдельно не подтверждён.
- Каждая команда создаёт свой публичный Git-репозиторий. Полноценного лидерборда, скорее всего, не будет (Николай).
- Модель любая: локальная, бесплатный или платный API. Для платной указать название и примерную стоимость одной полной оценки со всеми вызовами.
- Данные звонков реальные: транскрипты и подписанные ссылки не выкладывать публично.

## Не подтверждено

- Что именно сравнивают с Ground Truth: каждый критерий, итог, N/A, флаг или сочетание.
- Дадут ли размеченные DEV-примеры.
- Состав контрольных 10 диалогов (языки, каналы).
- ~~Формат передачи результатов организаторам~~: по словам Codex, есть Appendix к Student Guide (JSON 1.0), экспорт делают `tools/cqa_results.py` и `tools/run_cqa.py`. Сам Appendix в проекте не лежит и мной не проверялся, спецификацию Codex должен описать в `docs/RESULTS_FORMAT.md`.
- Нужен ли деплой. Guide требует репозиторий и README с шагами запуска, о деплое не говорит.
- Форма ссылки для контрольной группы: тот же адрес с другим `group_id` или отдельная подписанная ссылка.
- Как поступать со скрытыми именами и ошибками транскрипта.
- Как оценивать пограничные случаи завершения.
- Как ISO-время реплик звонка соотносится с позицией в аудио.
- Режим округления на точных половинах.
- Как порог первой реакции 3 минуты связан с критериями: в описаниях критериев минуты не упоминаются.
