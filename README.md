# CQA: Conversation Quality Analytics

Проект хакатона Data Challenge «Doomsday», кейс Freedom Broker. Сервис оценивает качество диалогов оператора с клиентом (чаты и звонки) по настраиваемому чек-листу: модель выбирает ответ по каждому критерию и цитату-доказательство, а итоговый балл считает код по формуле, а не модель.

> Статус: прототип готов к защите. Оценка, редактор чек-листа, апелляции и плеер звонков работают на Rust-бэкенде.

## Возможности

- Список диалогов группы `dev` или `control` с фильтрами по языку и каналу и поиском по id.
- Транскрипт диалога: роли (клиент, оператор, бот, система), метки времени как в данных.
- Оценка выбранного диалога: ответ по каждому критерию, баллы, объяснение, причина N/A, проверенный участок, цитаты-доказательства. Клик по цитате прокручивает транскрипт к реплике.
- Judge на модели (OpenAI-совместимый или Anthropic API): один запрос на критерий, цитата проверяется кодом, шкальные критерии берутся по медиане трёх запусков. Без настроенной модели возвращается заглушка с `"mock": true`.
- Редактор чек-листа: критерии, формулировки, веса, типы ответа, шкалы, N/A, секции, порядок. Каждое сохранение увеличивает версию, старые версии хранятся.
- Апелляции: оспорить критерий с комментарием, экран «Проверка» для проверяющего, решение «подтвердить» или «изменить» с причиной, пересчёт итога по версии чек-листа оценки.
- Плеер звонков: запись, смещение каждой реплики, перемотка по клику.
- Массовая оценка группы («Оценить все») с прогрессом.
- Ручная разметка диалогов и отчёт согласия модели с разметкой (`/api/labels`, `/api/report`).

## Быстрый старт

Нужен Rust (cargo). Проверялось на Windows.

```powershell
git clone https://github.com/Nurzhan-Zhumabekov/-pheonix-.git
cd .\-pheonix-
copy .env.example .env
# откройте .env и впишите DEV_API_URL и настройки модели (LLM_*)
cd backend
cargo run
```

Интерфейс откроется на http://127.0.0.1:8080 (сервер слушает только localhost). Сервер запускают из папки `backend/`. Файл `.env` ищется в корне репозитория.

Тесты: `cd backend && cargo test`.

Без `LLM_PROVIDER` оценка идёт через заглушку, остальное (чек-лист, расчёт итога, апелляции, метки) работает по-настоящему.

## Настройки

Переменные задаются в `.env` (шаблон: `.env.example`).

| Переменная | Что это |
|---|---|
| `DEV_API_URL`, `CONTROL_API_URL` | Адреса API организаторов (подписанные ссылки). Секрет, в git не попадает. |
| `LLM_PROVIDER` | `openai` (OpenAI-совместимый, в том числе Ollama) или `anthropic`. Пусто: заглушка. |
| `LLM_MODEL`, `LLM_API_KEY`, `LLM_BASE_URL` | Модель, ключ (секрет) и адрес, если не стандартный. |
| `LLM_REASONING_EFFORT` | Для openai-протокола, `none` отключает рассуждения. |
| `LLM_VOTES`, `LLM_CONCURRENCY`, `LLM_MAX_TOKENS` | Запусков для шкальных критериев, одновременных запросов, лимит ответа. |
| `LLM_PRICE_IN`, `LLM_PRICE_OUT` | Цена за 1 млн токенов, USD, для расчёта стоимости оценки. |
| `PROMPTS_DIR` | Каталог с шаблонами промптов (`config/prompts`). |
| `PORT`, `STORAGE_DIR`, `WEB_DIR` | Порт, хранилище (по умолчанию `storage` в корне), каталог интерфейса. |

## Эндпоинты

Полный контракт с форматами: [docs/API_CONTRACT.md](docs/API_CONTRACT.md).

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | Проверка, что сервер жив |
| `GET /api/conversations?group=dev\|control` | Список диалогов |
| `GET /api/conversations/{id}` | Диалог целиком: транскрипт, `audio_url` |
| `GET /api/checklist`, `PUT /api/checklist`, `GET /api/checklists/{version}` | Чек-лист, сохранение (версия растёт на 1), версия из архива |
| `POST /api/evaluate` | Оценить диалог, сохранить и вернуть результат |
| `GET /api/evaluations/{id}` | Последняя сохранённая оценка |
| `POST /api/appeals`, `GET /api/appeals`, `POST /api/appeals/{id}/resolve` | Апелляции и решение проверяющего |
| `GET /api/labels`, `GET/PUT /api/labels/{id}`, `GET /api/report` | Ручная разметка и отчёт согласия |

Ошибки всегда в формате `{"error": {"code": "...", "message": "..."}}` с HTTP-статусом.

## Как считается итог

Итог = `100 × Σ(вес × доля) / Σ(вес)` по применимым критериям. «Да» = 1, «Нет» = 0, значение шкалы = значение / максимум шкалы. Критерии с N/A исключаются из обеих сумм; если применимых критериев с весом нет, итог `null`. Округление до двух знаков (half up). Подробнее: [docs/SCORING.md](docs/SCORING.md).

## Данные и безопасность

- `.env`, `storage/`, `results/` и `data/raw/` в `.gitignore`. Адреса API организаторов (подписанные ссылки), ключи моделей, записи звонков и выгрузки с цитатами в репозиторий не попадают.
- Интерфейс обращается только к нашему `/api`. К API организаторов ходит бэкенд, ссылка не попадает в браузер.
- Результаты не заготовлены заранее: любой диалог оценивается на лету.

## Модель и стоимость

| Параметр | Значение |
|---|---|
| Модель | `gpt-6.1-terra` (выбор Нуржана; `gpt-6-luna` дешевле примерно в 10 раз) |
| Тип | облачная (OpenAI API); локальная Qwen3.5-4B через Ollama как запасной вариант |
| Вызовов на одну полную оценку | 12 (8 критериев, 2 шкальных по 3 запуска) |
| Стоимость одной полной оценки | Измерено на 20 размеченных диалогах DEV: 0,5353 USD, около 0,027 USD на диалог (12 запросов, 69 секунд на все 20 при трёх оценках одновременно). Все 65 диалогов DEV на Terra выйдут примерно на 1,7 USD (оценка). На Luna в десять раз дешевле, но точность ниже: 74,4% (старые метки) против 92,5% (исправленные метки, оговорки в docs/ML_APPROACH.md) |
