# CQA: Conversation Quality Analytics

Проект хакатона Data Challenge «Doomsday», кейс Freedom Broker. Сервис оценивает качество диалогов оператора с клиентом (чаты и звонки) по настраиваемому чек-листу: модель выбирает ответ по каждому критерию и цитату-доказательство, а итоговый балл считает код по формуле, а не модель.

> **Важно: сейчас оценка идёт через заглушку `mock`.** Ответы по критериям задаются простым правилом, а не моделью, поэтому в результате стоит `"mock": true`, а в карточке плашка «mock». Интерфейс, чек-лист, расчёт итога и апелляции при этом работают по-настоящему. После подключения judge эта заметка будет удалена.

## Возможности

- Список диалогов группы `dev` или `control` с фильтрами по языку и каналу и поиском по id.
- Транскрипт диалога: роли (клиент, оператор, бот, система), метки времени как в данных.
- Оценка выбранного диалога: ответ по каждому критерию, баллы, объяснение, причина N/A, проверенный участок, цитаты-доказательства. Клик по цитате прокручивает транскрипт к реплике и подсвечивает её.
- Редактор чек-листа: критерии, формулировки, веса, типы ответа, шкалы, N/A, секции, порядок. Каждое сохранение увеличивает версию; результат, полученный по старой версии, помечается подсказкой.
- Апелляции: оспорить критерий с комментарием; экран «Проверка» для проверяющего с фрагментом диалога, решением «подтвердить» или «изменить» с причиной и блоком «Было → Решение → Стало». Итог пересчитывается.
- Плеер звонков: запись, смещение каждой реплики в формате ММ:СС, перемотка по клику и кнопка «▶ к записи» у доказательства.
- Массовая оценка группы («Оценить все») с прогрессом, остановкой и списком ошибок.

## Быстрый старт

Нужен Python 3.10 или новее (проверялось на Python 3.12).

**Windows (PowerShell)**

```powershell
git clone https://github.com/Nurzhan-Zhumabekov/-pheonix-.git
cd .\-pheonix-
copy .env.example .env
# открой .env и впиши DEV_API_URL (CONTROL_API_URL можно добавить позже)
cd backend
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m uvicorn main:app --reload
```

**Mac и Linux**

```bash
git clone https://github.com/Nurzhan-Zhumabekov/-pheonix-.git
cd ./-pheonix-
cp .env.example .env
# открой .env и впиши DEV_API_URL (CONTROL_API_URL можно добавить позже)
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --reload
```

После запуска:

- интерфейс: http://127.0.0.1:8000/
- документация API (генерируется автоматически): http://127.0.0.1:8000/docs

Сервер запускают из папки `backend/`. Файл `.env` ищется в корне репозитория.

**Тесты** (из папки `backend/`, с активным окружением или через путь к нему):

```powershell
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
```

На Mac и Linux: `.venv/bin/pip install -r requirements-dev.txt` и `.venv/bin/python -m pytest`. Тесты работают во временной папке и не трогают `storage/`.

## Настройки

Переменные задаются в `.env` (шаблон: `.env.example`).

| Переменная | Что это |
|---|---|
| `DEV_API_URL` | Полный адрес API организаторов для группы `dev` (подписанная ссылка вместе с `group_id`). Секрет, в git не попадает. |
| `CONTROL_API_URL` | То же для контрольной группы. Если пусто, `group=control` возвращает понятную ошибку. Форма адреса меняется только в `.env`. |
| `LLM_PROVIDER` | Провайдер модели для judge. Зарезервирована, пока не используется (оценка идёт через заглушку). |
| `LLM_MODEL` | Название модели для judge. Зарезервирована, пока не используется. |
| `LLM_API_KEY` | Ключ модели. Зарезервирована, пока не используется. Секрет. |
| `STORAGE_DIR` | Папка хранилища (чек-лист, оценки, апелляции). По умолчанию `storage` в корне репозитория. |

## Эндпоинты

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | Проверка, что сервер жив: `{"ok": true}` |
| `GET /api/conversations?group=dev\|control` | Список диалогов: `conversation_id`, `channel`, `language`, `turns_count`, `has_evaluation` |
| `GET /api/conversations/{id}` | Диалог целиком: транскрипт, `audio_url` |
| `GET /api/checklist` | Текущий чек-лист |
| `PUT /api/checklist` | Сохранить чек-лист целиком с проверкой; версия растёт на 1 |
| `POST /api/evaluate` | Оценить диалог `{conversation_id}`, сохранить и вернуть результат |
| `GET /api/evaluations/{conversation_id}` | Последняя сохранённая оценка |
| `POST /api/appeals` | Подать апелляцию `{conversation_id, criterion_id, comment}` |
| `GET /api/appeals?conversation_id=` | Апелляции диалога (без параметра все) |
| `POST /api/appeals/{id}/resolve` | Решение проверяющего `{action: confirm\|change, new_answer, reason}` |

Ошибки всегда в формате `{"error": {"code": "...", "message": "..."}}` с HTTP-статусом. Подробные форматы чек-листа, оценки и апелляции описаны в `CLAUDE.md` (раздел «Контракт API»).

## Как считается итог

Итог = `100 × Σ(вес × доля) / Σ(вес)` по применимым критериям. «Да» = 1, «Нет» = 0, значение шкалы = значение / максимум шкалы. Критерии с N/A исключаются из обеих сумм; если применимых критериев с весом нет, итог `null`. Округление до двух знаков. Веса и критерии задаёт чек-лист (`config/default_checklist.json`, описание в `CLAUDE.md`, раздел «Чек-лист по умолчанию»). Пересчёт при решении апелляции делает тот же код на бэкенде; фронт формулу не дублирует.

Сейчас формулу выполняет временный модуль `backend/scoring_stub.py`, он будет заменён на scoring из ML-части.

## Данные и безопасность

- `.env`, `storage/` и `data/raw/` в `.gitignore`. Адреса API организаторов (подписанные ссылки), ключи моделей и записи звонков в репозиторий не попадают.
- Фронт обращается только к нашему `/api`. К API организаторов ходит бэкенд; ссылки на них нет ни в коде, ни в интерфейсе. `audio_url` приходит в браузер из нашего API и используется только как адрес записи в плеере.
- Данные организаторов бэкенд держит в памяти процесса и на диск не пишет. После перезапуска сервера они загружаются заново. В `storage/` лежат только данные самого сервиса: чек-лист, оценки (в них есть цитаты реплик) и апелляции.
- Заготовленных результатов нет: любой диалог оценивается на лету. Пока judge не подключён, результат строит заглушка (см. заметку выше).

## Допущения

- Округление итога: half up до двух знаков.
- Пояснения к оценке на русском языке.
- Реплики бота и системы используются только как контекст, оценивается оператор.
- Позиция реплики звонка в аудио = время реплики минус время первой реплики диалога (допущение A2 из документов ML-части). Совпадение с реальной записью не подтверждено.
- Для чатов метки времени `MM:SS` показываются как пришли, для звонков ISO 8601 с поясом тоже как пришли, плюс смещение ММ:СС.

Организаторы пока не подтвердили (уточняется): что именно сравнивается с Ground Truth; будут ли размеченные DEV; состав контрольных 10 диалогов; нужен ли деплой; форма ссылки на контрольную группу; привязка времени звонка к аудио; режим округления; роль порога первой реакции в 3 минуты.

## Модель и стоимость

Поля заполнит Нуржан после подключения judge. Значения не заполнены намеренно.

| Параметр | Значение |
|---|---|
| Модель | заполнит Нуржан |
| Тип (провайдер, версия) | заполнит Нуржан |
| Число вызовов на одну оценку | заполнит Нуржан |
| Стоимость одной оценки | заполнит Нуржан |

В результате оценки эти данные возвращаются в поле `model` (`name`, `calls`, `input_tokens`, `output_tokens`, `cost_usd`). Сейчас там заглушка: `name = "mock"`, нулевые значения.
